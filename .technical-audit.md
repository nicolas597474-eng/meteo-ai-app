# Audit technique ciblé — 20 août 2026

## Défauts confirmés

- Le graphique horaire affiche deux jours consécutifs. Les libellés `00:00` à `23:00` sont donc légitimement répétés, mais la clé React utilisée est seulement `h.hour`. Cette clé n’est pas unique et déclenche un avertissement React reproductible.
- Le graphique affiche ces 48 créneaux alors que son indicateur d’en-tête indique statiquement `24h⌄`. Le libellé est donc incohérent avec les données réellement visibles.

## Éléments non modifiés sans preuve supplémentaire

- Les sections qualité de l’air et Soleil & Lune déclarent explicitement des données réelles indisponibles. Elles ne doivent pas être remplacées par des valeurs estimées.
- L’ancienne erreur `Response.clone: Body has already been consumed` existe dans les journaux historiques, mais elle n’est pas reproduite par le rendu actuel. Le cache HTTP sera renforcé par un test de consommation de la première réponse avant toute correction éventuelle.

## Contrôles post-correctif

Le correctif remplace la clé fondée sur l’heure seule par une clé combinant heure et position du créneau. Le badge de durée est désormais calculé à partir du nombre réel de créneaux. Après rechargement, le Dashboard a démarré normalement ; le contrôle de console de la session rechargée reste à effectuer.

Le Dashboard corrigé affiche désormais `48 h`, conformément aux 48 créneaux réellement fournis. La console de cette session rechargée ne présente aucun avertissement ni erreur. Les tests confirment également que le cache HTTP reste lisible après consommation de la première réponse ; l’erreur historique de corps consommé ne nécessite donc pas de modification de production sans reproduction fiable.

## Vérification du séparateur de journée

Le Dashboard mobile affiche le repère `Demain` au créneau de minuit suivant, en cohérence avec les 48 heures disponibles. Aucun avertissement de console n’est émis après le rendu. Le contrôle manuel de la croix locale nécessite un lieu actif avec le mode Local ou Ultra-local, indisponible dans la session de prévisualisation non authentifiée ; son comportement est couvert par le gestionnaire existant qui restaure explicitement le mode Officiel.
